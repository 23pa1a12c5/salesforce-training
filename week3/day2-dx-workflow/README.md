# Day 2 – Salesforce DX Workflow

## What is Salesforce DX?

Salesforce DX (Developer Experience) is a modern development approach used in Salesforce for source-driven development, testing, deployment, and team collaboration.

It helps developers:
- Create scratch orgs
- Use source control
- Automate deployments
- Improve development workflows
- Manage application lifecycle efficiently

Salesforce DX supports modern DevOps practices in Salesforce projects.

---

# Why CLI Matters

Salesforce CLI (Command Line Interface) is a tool used to perform Salesforce development operations using commands.

CLI helps developers:
- Create scratch orgs
- Deploy code
- Retrieve metadata
- Run tests
- Automate tasks

CLI improves development speed and reduces manual work.

---

# Why GitHub Matters

GitHub is used for version control and collaboration in Salesforce projects.

GitHub helps teams:
- Store project code safely
- Track changes
- Collaborate efficiently
- Manage project versions
- Review code before deployment

GitHub is important in enterprise development because multiple developers work on the same project.

---

# Team Collaboration Problems

Without proper collaboration tools, teams may face:
- Code conflicts
- Duplicate work
- Deployment issues
- Loss of code versions
- Difficult project tracking

Salesforce DX and GitHub help solve these problems using version control and structured workflows.

---

# Enterprise Workflow Discussion

A typical enterprise Salesforce workflow includes:

1. Developer creates features in scratch org
2. Code is managed using GitHub
3. Testing is performed
4. Team reviews code changes
5. Code is deployed to higher environments
6. Final deployment is done to production

This workflow improves:
- Code quality
- Collaboration
- Deployment reliability
- Project management
